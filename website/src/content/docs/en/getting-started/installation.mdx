Seshat ships as a single binary. Pick the route that fits you: a one-line install script for end users (a shell script on Linux and macOS, a PowerShell script on Windows), the Go toolchain for developers, or a source build if you want to hack on it.

<Callout type="note" title="Platforms">
There is an install script for **Linux** and **macOS** and one for **Windows**, all on `amd64` and `arm64`. The terminal interface is used on Windows Terminal; other Windows setups have had less testing.
</Callout>

## Which command for which system

| System | Command | Needs |
|---|---|---|
| **Linux** (amd64, arm64) | `curl -fsSL https://raw.githubusercontent.com/KPO-Tech/seshat-runtime/main/scripts/install.sh \| bash` | `curl` or `wget`, a shell |
| **macOS** (Intel, Apple silicon) | the same command as Linux | `curl`, a shell |
| **Windows** (amd64, arm64) | `irm https://raw.githubusercontent.com/KPO-Tech/seshat-runtime/main/scripts/install.ps1 \| iex` in PowerShell | nothing else, no administrator rights |

None of them needs Go: the script downloads a ready-made binary. Whatever the system, the command you type afterwards is `seshat`.

## Install with the script on Linux and macOS

<Steps>

1. **Run the installer.**

   ```bash
   curl -fsSL https://raw.githubusercontent.com/KPO-Tech/seshat-runtime/main/scripts/install.sh | bash
   ```

2. **Reload your shell** if the installer asks you to, or open a new terminal. The installer adds `~/.local/bin` to your `PATH`.

3. **Check the installation.**

   ```bash
   seshat version
   ```

</Steps>

### What the script does

- Detects your system and downloads the matching binary from the GitHub release.
- Verifies its SHA-256 checksum, and stops if it does not match.
- Installs it in `~/.local/bin` and adds that folder to your shell profile if needed.
- Prepares the runtime folder `~/.config/seshat-cli/` (it follows `XDG_CONFIG_HOME` when set). The database and your sessions are created on first run.

### Options

```bash
# Pin a specific version
VERSION=v1.5.0 bash <(curl -fsSL https://raw.githubusercontent.com/KPO-Tech/seshat-runtime/main/scripts/install.sh)

# Install somewhere else
INSTALL_DIR=/usr/local/bin bash <(curl -fsSL https://raw.githubusercontent.com/KPO-Tech/seshat-runtime/main/scripts/install.sh)
```

## Install on Windows

<Steps>

1. **Open PowerShell** and run the installer. It does not need administrator rights.

   ```powershell
   irm https://raw.githubusercontent.com/KPO-Tech/seshat-runtime/main/scripts/install.ps1 | iex
   ```

2. **Open a new terminal** if `seshat` is not found: the installer adds its folder to your user `PATH`, which only new terminals read.

3. **Check the installation.**

   ```powershell
   seshat version
   ```

</Steps>

### What the Windows script does

- Picks the build for your processor (`amd64` or `arm64`) and downloads it from the GitHub release.
- Verifies its SHA-256 checksum, and stops before writing anything if it does not match.
- Installs `seshat.exe` in `%LOCALAPPDATA%\Programs\seshat` and adds that folder to your user `PATH`.
- Installs [ripgrep](https://github.com/BurntSushi/ripgrep) with winget, scoop or choco when it is missing: the `glob` and `grep` tools need it. If none of them is available, the script tells you where to get it.
- Uses the runtime folder `%APPDATA%\seshat-cli\`. The database and your sessions are created on first run.

### Windows options

Set these variables in the same PowerShell session, before the command.

```powershell
# Pin a specific version
$env:SESHAT_VERSION = "v1.9.0"

# Install somewhere else
$env:SESHAT_INSTALL_DIR = "C:\tools\seshat"

# Do not try to install ripgrep
$env:SESHAT_SKIP_RIPGREP = "1"
```

To make `shift+Enter` insert a new line in Windows Terminal or VS Code, run `seshat terminal-setup`.

## Update

An installed `seshat` tells you when a new release is published. When you start it in a terminal, it checks the latest release (at most once a day, with a two-second limit, and silently when you are offline) and asks:

```text
seshat v1.10.0 is available (you have v1.9.0).
Update now? [Y]es / [l]ater / [s]kip this version:
```

- **Yes** (or Enter) downloads the new binary, checks it against the release's `SHA256SUMS.txt` and puts it in place of the running one. Start `seshat` again to use it. If anything fails, the old binary stays where it is.
- **Later** stays quiet for a day. **Skip** stays quiet until a newer release comes out.

You can also update whenever you want:

```bash
seshat update           # look for a newer release, ask, install
seshat update --check   # only say whether there is one
seshat update --yes     # install without asking
```

Set `SESHAT_NO_UPDATE_CHECK=1` to turn the offer off. It is never shown for a development build, in a pipe or in CI. Running the install script again also updates, and is the way to get the `seshat update` command on a version that does not have it yet.

<Callout type="note" title="How the download is checked">
The checksum proves that the download is intact. The trust in who published it is the one you already place in the GitHub release when you run the install script.
</Callout>

## Name sessions on your machine (optional)

By default the chat provider gives each session a title after your first message. If you prefer that to happen offline, for free and without showing that message to the provider again, install a small model that runs on your CPU:

```bash
seshat title-model install
```

The command downloads the [llama.cpp](https://github.com/ggml-org/llama.cpp) server (a CPU build of 12 to 19 MB) and the Qwen2.5 0.5B Instruct model (about 470 MB). It checks both against checksums fixed inside seshat, then starts the model once to show that it answers. On a laptop CPU the first title takes under two seconds and the next ones less than half a second.

- Both install scripts offer it at the end. Set `SESHAT_TITLE_MODEL=1` to install it without being asked, or `0` to skip the question.
- `seshat title-model install --model gemma-3-270m` installs a smaller model (about 240 MB): faster, with rougher titles.
- `seshat title-model status`, `disable`, `enable` and `remove` manage it. The model server only runs while seshat is open and stops after ten idle minutes.
- If the model is not installed, is turned off or fails, the chat provider names the session as before.

### Where it lives and what it uses

- Files: the folder `title-model/` inside the runtime folder (`~/.config/seshat-cli/` on Linux and macOS, `%APPDATA%\seshat-cli\` on Windows). It holds the llama.cpp server, the model, a `state.json` and the server's `server.log`. `seshat title-model remove` deletes the folder.
- Memory and CPU: the server listens on the loopback address only, so nothing outside your machine can reach it. It uses about 600 MB of memory while it runs and the processor for a fraction of a second per title. It starts with the first title, and stops after ten idle minutes and when seshat exits.
- Crashes: if seshat is killed, the next run notices the server left behind and stops it, but only if that server still has this exact model loaded, so another program is never touched.
- Supported systems: Windows, Linux and macOS, on `amd64` and `arm64`. On another system the command says so and the provider keeps naming sessions.

A 0.5-billion-parameter model gives plain titles. The provider's are usually better; the local model trades some quality for speed, cost and privacy.

## Install with the Go toolchain

You need **Go 1.26 or later**.

```bash
go install github.com/KPO-Tech/seshat-runtime/tui/cmd/cli@latest
```

The command installs a binary called `cli`; rename it to `seshat` or use the install script, which names it for you. The terminal interface is a module of its own (`tui`), so this path exists from the first release that includes it; earlier releases use `github.com/KPO-Tech/seshat-runtime/cmd/cli@latest`.

## Build from source

```bash
git clone https://github.com/KPO-Tech/seshat-runtime
cd seshat-runtime
make build
```

This produces two binaries in `bin/`:

| Binary | Purpose |
|---|---|
| `bin/seshat` | Interactive terminal agent: chat, run tools, manage sessions |
| `bin/seshat-grpc` | gRPC server, to embed Seshat in a larger system |

## Use it as a library

To embed the runtime in your own Go application, add the SDK to your module:

```bash
go get github.com/KPO-Tech/seshat-runtime@latest
```
