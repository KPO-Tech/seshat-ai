Seshat needs at least one model provider. You can set it up from the command line, from the terminal interface, or with environment variables.

## From the command line

```bash
seshat config --provider anthropic --api-key sk-ant-...   # set a provider and its key
seshat config --model anthropic:claude-sonnet-4-20250514  # choose the model (provider:model)
seshat config --print                                     # show the current configuration
```

`seshat config` also takes `--region`, `--project-id`, `--base-url` and `--resource` for the cloud providers, `--cwd` for the default working directory, `--db` for the database path, and `--search` to set only the web search keys. The keys you save this way are stored **encrypted**, per provider, in the local database.

In the terminal interface, press `ctrl+,` for providers and `ctrl+m` for models.

<Callout type="warning" title="Keys entered in the terminal interface">
A key entered in the providers screen is saved in `seshat.json`, in the runtime folder (described below). The file is readable only by you, but the key is **not encrypted**. To keep a key out of a file, leave the field empty and use an environment variable instead.
</Callout>

## With environment variables

Set the variable of the provider you want. This is the simplest way for servers and scripts:

```bash
export ANTHROPIC_API_KEY=sk-ant-...
```

The main variables are `SESHAT_MODEL` (`provider:model`), `SESHAT_API_KEY`, `SESHAT_RUNTIME_ROOT`, `SESHAT_DB_PATH`, `SESHAT_CWD`, `SESHAT_DEBUG`, and for the cloud providers `SESHAT_PROVIDER_BASE_URL`, `SESHAT_PROVIDER_REGION`, `SESHAT_PROVIDER_PROJECT_ID` and `SESHAT_PROVIDER_RESOURCE`.

<Callout type="note" title="Where things are stored">
The runtime folder holds the configuration file, the local SQLite database with your sessions, the logs and the documents. For the `seshat` binary it is `~/.config/seshat-cli/` (or `$XDG_CONFIG_HOME/seshat-cli/`, and `%APPDATA%\seshat-cli\` on Windows). A Go program that embeds the SDK uses `~/.config/seshat/` by default. `SESHAT_RUNTIME_ROOT` moves it.
</Callout>

The models each provider offers, with their context sizes and capabilities, are in [Providers and models](/en/docs/reference/models).

## Optional tools

Some tools exist in every installation but do nothing until you give them what they need.

| Tool | What it does | What it needs |
|---|---|---|
| `generate_image` | Image generation | An `image_generation` provider (`openai` or `gemini`) in the configuration, and a key. It reuses the key of your model provider when they are the same |
| `text_to_speech`, `speech_to_text` | Speech synthesis and transcription | A `text_to_speech` or `speech_to_text` provider in the configuration, and a key |
| `web_search` | Search the web | A key for one search service: `TAVILY_API_KEY`, `EXA_API_KEY`, `JINA_API_KEY` or `LANGSEARCH_API_KEY`, or `SEARXNG_BASE_URL`. `seshat config --search` sets them. `WEB_SEARCH_PROVIDER` picks the service |
| `devto_publish` | Publish to DEV | `DEV_TO_API_KEY` |
| `notebook_*` | Work in a live Jupyter kernel | `JUPYTER_SERVER_URL` (default `http://localhost:8888`) and `JUPYTER_TOKEN` |

<Callout type="tip" title="Search tools need ripgrep">
The `glob` and `grep` tools use [ripgrep](https://github.com/BurntSushi/ripgrep). Install it with your package manager if you do not have it.
</Callout>
