The terminal interface and the `seshat` command read their settings from JSON files named `seshat.json`. This page lists the files, the order in which they apply, and every key. For the usual ways to set a provider and a model without editing a file, see [Configuration](/en/docs/getting-started/configuration). A Go program that embeds the runtime does not use these files: it uses [ClientConfig](/en/docs/reference/client-config).

## Where the files are

| File | Scope |
|---|---|
| `seshat.json` in the runtime folder | Global: your own settings, for every project. The runtime folder is described in [Configuration](/en/docs/getting-started/configuration). `SESHAT_GLOBAL_CONFIG` points to another folder |
| `seshat.json` or `.seshat.json` in the project | Project: found from the working directory up to the root of the git repository. A file above the repository is never read |
| `.seshat/seshat.json` in the project | Workspace: the file that Seshat itself writes when you change a setting for one project |

The files are merged. When the same key is set twice, the file closest to the project wins over the global one.

## Projects you do not trust

A repository you just cloned can carry any of these files. Some sections start programs or decide where your keys go, so the terminal interface **ignores them until you trust the project** with `seshat trust`:

- `mcp` and `mcpServers`
- `lsp`
- `hooks`
- `permissions`
- `providers`
- `image_generation`, `text_to_speech` and `speech_to_text`
- `options.context_paths` and `options.skills_paths`

The other sections still apply: `models`, the display options and the tools you disable. Your own global file is never restricted. Trust is recorded for the exact content of each file, so a change brings the question back. See [Security and trust](/en/docs/concepts/security-and-trust#project-files-are-not-trusted-until-you-say-so).

## An example

```json
{
  "models": {
    "large": { "provider": "anthropic", "model": "claude-sonnet-4-20250514" }
  },
  "options": {
    "tui": { "compact_mode": true },
    "disabled_tools": ["monitor"]
  },
  "permissions": {
    "allowed_tools": ["glob", "grep"]
  },
  "mcp": {
    "github": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"]
    }
  },
  "hooks": {
    "pre_tool_use": [
      { "matcher": "bash", "command": "./scripts/check-command.sh", "timeout": 10 }
    ]
  }
}
```

The `mcp` and `permissions` sections of a project file would be ignored until the project is trusted.

### `models`

One entry per model type, `large` and `small`. Each entry has these keys.

| Key | Type | Default | Meaning |
|---|---|---|---|
| `model` | string, required |  | The model ID as used by the provider API |
| `provider` | string, required |  | The model provider ID that matches a key in the providers config |
| `reasoning_effort` | string |  | Reasoning effort level for OpenAI models that support it. One of `low`, `medium`, `high`. |
| `think` | boolean |  | Enable thinking mode for Anthropic models that support reasoning |
| `max_tokens` | number |  | Maximum number of tokens for model responses |
| `temperature` | number |  | Sampling temperature |
| `top_p` | number |  | Top-p (nucleus) sampling parameter |
| `top_k` | number |  | Top-k sampling parameter |
| `frequency_penalty` | number |  | Frequency penalty to reduce repetition |
| `presence_penalty` | number |  | Presence penalty to increase topic diversity |
| `provider_options` | object |  | Additional provider-specific options for the model |
