A tool is something the model can ask Seshat to do: read a file, run a command, search the web. Each tool is declared, and the agent only uses the ones it is given. Sensitive calls ask for your approval first, as described in [Security and trust](/en/docs/concepts/security-and-trust).

<Callout type="note" title="Generated from the code">
The tables below are written by `npm run sync:tools` from the real registry of the runtime, so they follow the code. Only the introduction and the notes around them are written by hand.
</Callout>

## How to read the tables

- **Read-only** says whether the tool changes nothing. The runtime treats a read-only call more leniently and may run several in parallel.
- **Available** says whether the tool is offered to the model. "Yes" means it is active without any configuration. Otherwise it names what is missing: a provider, a key or a service. A tool that is not available is left out of the list the model sees.
- To add your own tools in Go, see [Tools](/en/docs/sdk/tools). Tools from MCP servers are described in [Skills and MCP](/en/docs/concepts/skills-and-mcp).

## Limit the tools of an agent

You do not have to give an agent every tool. A sub-agent type has its own tool list, and the `tools` parameter of a call narrows it further. See [Agents and delegation](/en/docs/concepts/agents-and-delegation). `ManagedPolicy.ForbiddenTools` in [ClientConfig](/en/docs/reference/client-config) removes tools for every agent of a host.
