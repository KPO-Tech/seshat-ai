The system prompt is built every turn from layers. You customise it with a `PromptConfig`, without touching the core sections.

## How it is assembled

<Diagram {...promptStack} />

1. **Core sections**: identity, runtime contract, working rules, tool use, output discipline and more. They never change, which is why they can be cached by the provider.
2. **Runtime context**: session, turn number, working directory, model, available tools.
3. **Runtime guidance**.
4. **Project instructions**, when the working directory has them (see below).
5. **Memory context**, when memory is enabled.
6. **Stage overlay**, when you set a stage other than the default.
7. **Your appended text**, always last.

Tool definitions sent to the provider come from the tool registry. Your hints are added to their descriptions.

### Project instructions

If the working directory contains an instructions file, its content is added to the prompt every turn, before the memory context. Seshat looks for these files in order and uses **the first one that is not empty**:

1. `SESHAT.md`
2. `AGENTS.md`
3. `.seshat/instructions.md`

The content is cut at 32 KB. Use it for rules that belong to a project: how to build and test, conventions, things to avoid.

<Callout type="warning" title="Instructions come from the project">
A project you just cloned can carry an instructions file, and its text reaches the model as instructions. Read an unfamiliar `AGENTS.md` before you run an agent in that folder.
</Callout>

## Configure it

```go
extra := "Always answer in French. Prefer small, reviewable changes."

cfg := sdk.DefaultClientConfig()
cfg.PromptConfig = &sdk.PromptConfig{
    AppendSystemPrompt: &extra,
    ToolHints: map[string]string{
        "bash": "Prefer `rg` over `grep`. Never run commands that need a TTY.",
    },
}
```

| Field | Effect |
|---|---|
| `AppendSystemPrompt` | Text added after everything else, every turn. The safest way to add rules |
| `SystemPrompt` | **Replaces** the whole default prompt. The core sections and stage overlay are then not used |
| `ToolHints` | Per-tool guidance added to a tool's description, keyed by tool name |
| `Stage` | An overlay for how the model should behave this turn (see below) |
| `StageOverrides` | Replace the built-in overlay text of a stage |

<Callout type="warning" title="Replacing the prompt">
`SystemPrompt` removes the instructions that make the agent use tools safely and consistently. Prefer `AppendSystemPrompt` unless you are building something very different.
</Callout>

## Stages

A stage adds a short instruction for a situation:

| Stage | Meaning |
|---|---|
| `StageDefault` | Normal operation, nothing added |
| `StageToolCall` | The model is expected to call tools |
| `StageToolResult` | The model should work with the tool results it received |
| `StageContinuation` | Resume from where it stopped |
| `StagePlan` | Plan mode overlay: the model is told to describe a plan instead of running tools |

For normal use you do not set a stage. `StagePlan` is the one most apps use, to let the user review a plan first.

## On one session

A session can change its prompt after creation:

```go
session.SetAppendSystemPrompt("This conversation is about the billing service.")
session.SetSystemPromptTemplate(template)
session.SetWorkingDirectory("/srv/projects/billing")
```
