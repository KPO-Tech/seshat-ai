# Part VI — MVP

A successful product is not defined by the number of features it includes. It is defined by its ability to solve a meaningful problem exceptionally well.

Seshat has been designed as a long-term Enterprise Capability Platform. However, bringing such a platform to market requires focus, discipline and incremental execution.

The objective of the MVP is therefore not to expose every capability envisioned for the platform. Its purpose is to validate the core principles of Seshat within real organizations, generate measurable business value and establish a solid foundation for future expansion.

This chapter describes the MVP as it was actually decided — not as a top-down feature list, but by cross-checking what's genuinely real against the needs surfaced while working through concrete go-to-market cases (see `7.go-to-market-africa.md`). What gets built here is what's needed to negotiate and sell, not the other way around.

---

# 22. MVP Scope

## Design Philosophy

The MVP focuses on solving a limited number of high-value enterprise problems exceptionally well, using what's already solid rather than what sounds complete on paper. Rather than overwhelming users with numerous modules, Seshat provides a simple and unified experience centered around enterprise intelligence.

This means the scope below is intentionally uneven: some pieces are ready end-to-end, some are solid underneath but still need an interface, and one is a genuinely new build. That unevenness is stated plainly rather than smoothed over, because it's what actually determines what can be sold today versus what's still being built.

---

## What's In This MVP

<!-- DIAGRAM: status -->

### Company Assistant (Companion) — ✅ Ready, end to end

Chat, sessions, streaming, multi-provider support, and document reading (Docling or PaddleOCR, depending on configuration, already part of its read tools) all work today, including in the desktop app. This is the most complete piece of the platform and the base every customer gets.

### Knowledge (RAG) — 🟢 Backend solid, 🟡 desktop/console interface in progress

The retrieval pipeline itself — hybrid search, ingestion, embedder configuration — is real across `seshat`, `seshat-backend` and `seshat-server`, and has been verified end-to-end against a real model. What's left for this MVP is finishing the desktop and console experience around it, not the retrieval capability itself.

### Skills — 🟡 Deliberately descoped for this MVP

Reduced to viewing and reading (possibly light editing of) existing MCP-backed skills. Skill *creation* already exists in the current desktop code, but is intentionally left out of this MVP's surface area — not because it's broken, but to keep the MVP's scope small and stable while Company Assistant and Inbox Agent get hardened first.

### Scheduling — 🟡 Implemented, verification pending

Cron-based scheduled jobs, TaskAgent, job history — fully implemented, both locally and in the multi-tenant control plane. Not yet verified in real use; the blocker is a hardware upgrade for the developer, not missing code.

### Inbox Agent — 🚧 In active development, ~2-month target

The one genuinely new build in this MVP. It is not blocked by document handling — attachments can already be read using the same tools Company Assistant uses today.

---

## Explicitly Not In This MVP

- **Documents, in the full enterprise sense** (`4.product.md` chapter 11) — importing and organizing data by department/team (HR, Legal, etc.). The underlying ability to read a file is already real and already used elsewhere; what's missing is the department-organized product built around it. Mainly relevant to larger, more formal customers — not needed for the first pilots.
- **Accounting Agent, Prospecting Agent** — later Agent Workflows, sequenced against real demand rather than built speculatively (see `7.go-to-market-africa.md`'s build roadmap).
- **Meeting summarization from audio, image generation, PPTX generation** — the underlying capability exists at the engine level (`seshat/pkg/audio`, `pkg/image`) but isn't wired into the product UI yet, and hasn't been tested against paid, production-grade models — only free-tier/local ones so far.
- **Department-specific bespoke surfaces** (HR, data science, etc.) — sold case by case once a client needs one, not offered self-serve in this MVP.
- **Advanced Scheduling, Company Assistant across multiple devices, Enterprise Teams, Marketplace, autonomous long-running agents, cross-company collaboration, advanced enterprise analytics, industry-specific solution packs, governance dashboards, multi-organization federation** — long-term roadmap, untouched by this MVP.

---

## Who This MVP Already Serves

This MVP doesn't need every item above to close before it can be sold:

- An informal, relationship-based business is already fully served by Company Assistant and Scheduling alone — no blockers today.
- A formal SME with recurring back-office needs gets real value today (price comparison, structuring, drafting, calculations) and grows once Inbox Agent ships.
- A larger organization evaluating a self-hosted deployment is served today purely on Company Assistant's deployment story, independent of Inbox Agent entirely.

See `7.go-to-market-africa.md` for the concrete cases this maps to, and how each one's offer is scoped to exactly what's real.

---

> *This MVP is honest about what it is: mostly ready, partly waiting on an interface, and building exactly one new thing on purpose.*

# 23. Current Status

## Product Maturity

Seshat has progressed beyond experimentation. The engine and backend layers (`seshat`, `seshat-backend`, `seshat-server`) are consistently ahead of the interface layers (`seshat-ui`, `seshat-console`) — a pattern that showed up repeatedly while auditing this MVP: RAG, document reading, audio, image generation and financial calculations all exist and largely work underneath, while the corresponding desktop/console surfaces are what's still catching up.

---

## What Already Exists

### Solid end to end (engine, backend, and interface)

- Company Assistant: chat, sessions, streaming, multi-provider, document reading.
- Scheduled jobs infrastructure (implementation-complete; verification pending — see the testing gap below).

### Solid underneath, interface catching up

- Knowledge/RAG: hybrid search, ingestion, embedder configuration — verified end-to-end against a real model at the backend level; desktop/console experience not finished.
- Audio (`pkg/audio`, including planned whisper.cpp integration) and image generation (`pkg/image`) — real at the engine level, not yet wired into the product UI.
- Financial calculation tools — real, available as engine tools.
- General-purpose tools (bash, notebook read/edit) — real, available as engine tools; what's missing for department-specific surfaces is a tailored frontend, not the tools themselves.

### Governance and platform foundations

- Multi-user auth, organizations, workspaces, role-based permissions.
- Audit logging, usage quotas.
- Multi-provider AI abstraction with fallback.
- MCP client support.
- REST + streaming API surface.

---

## The Testing Gap

Two constraints apply across most of the above, and neither is a capability gap:

- **Hardware** — Scheduling is implemented but unverified in practice; the developer's current machine needs an upgrade before it can be tested comfortably.
- **Budget** — audio, image, and other engine-level tooling has only been exercised against free-tier or local models, never robustly tested against paid, production-grade ones.

"Works in the code" and "proven to work" are not the same claim anywhere in this document — that distinction should hold whenever any of this gets described to a real customer.

---

## Current Priorities

Current development effort focuses on:

- building Inbox Agent (the one new Agent Workflow in this MVP);
- finishing the Knowledge/RAG desktop and console experience on top of an already-solid backend;
- verifying Scheduling in real use once hardware allows it;
- validating the MVP's offer against real conversations in the field (see `7.go-to-market-africa.md`).

The objective is no longer to prove that Seshat can be built. It's to close the gap between what already works underneath and what a customer can actually see and use.

---

> *Most of what looked like missing capability turned out to be a missing interface. That changes what "finishing the MVP" actually means.*

# 24. Beyond the MVP

Once Inbox Agent ships and the Knowledge/RAG interface catches up to its backend, the next candidates — not yet sequenced — are:

- Accounting Agent (likely composed from existing Skills plus an external document-management project rather than built from scratch).
- Prospecting Agent (dual purpose: a sellable Agent Workflow, and an internal tool for Seshat's own outbound sales effort).
- Documents in the full enterprise, department-organized sense.
- Audio meeting summarization, image generation, and PPTX generation, wired into the product UI and tested against paid models.
- Department-specific bespoke surfaces (HR, data science, and others as real demand shows up).
- The longer-standing roadmap items: Advanced Scheduling, Company Assistant across multiple devices, Enterprise Teams, a Skills marketplace, autonomous long-running agents, cross-company collaboration, advanced analytics, industry-specific packs, governance dashboards, multi-organization federation.

Each of these gets built when a real, needs-driven case justifies it — not speculatively ahead of demand. See `7.go-to-market-africa.md` for how that sequencing gets decided.

---

> *The MVP is not a reduced version of Seshat. It's the honest subset of it that's actually ready to be sold today.*
