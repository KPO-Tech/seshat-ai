# Audit seshat-ai - 2026-08-02

## Synthese

Le projet est globalement sain cote compilation/tests: les tests Go passent,
le lint desktop passe, le lint console passe, le build console passe, et le
typecheck desktop passe. Les deux sujets prioritaires sont plutot
operationnels:

1. `make setup` ne couvre pas tout le monorepo et n'installe pas LibreOffice.
2. `make deploy-up` lance par defaut une stack trop large et lourde
   (`docling`, `minio`, `searxng`, `redis`, `mailpit`, builds Docker), ce qui
   explique le temps absurde au demarrage.

Il existe aussi une incoherence d'outillage: les scripts setup acceptent
Node.js 20+, alors que `seshat-ui/package.json` demande Node >=22 <25 et la CI
utilise Node 22.

## Verification effectuee

- `go test ./seshat-backend/... ./seshat-server/...`: OK.
- `npm run lint` dans `seshat-ui`: OK.
- `npm run lint` dans `seshat-console`: OK.
- `npm run typecheck` dans `seshat-ui`: OK.
- `npm run build` dans `seshat-console`: OK.
- `npm run build` dans `website`: KO localement car `tsc` est introuvable, ce
  qui indique que les dependances `website` ne sont pas installees localement.

Etat git observe au debut de l'audit: branche `dev`, avec des modifications
non commitees dans:

- `deploy/searxng/settings.yml`
- `seshat-ui/src/renderer/components/chat/ChatInput.tsx`
- `seshat-ui/src/renderer/components/chat/DocxPreviewPanel.tsx`
- `seshat-ui/src/renderer/pages/Conversation.tsx`
- `seshat-ui/src/renderer/pages/Home.tsx`
- `seshat-ui/src/renderer/stores/ui.ts`

Ces changements doivent etre consideres comme des changements utilisateur et ne
pas etre ecrases.

## Priorite 1 - Corriger `make setup`

### Probleme

`make setup` appelle seulement `scripts/setup.sh`. Ce script installe les
dependances de `seshat-ui`, installe docling, build les modules Go et build
le desktop. Il n'installe pas:

- LibreOffice / `soffice`
- les dependances `seshat-console`
- les dependances `website`

En pratique, un checkout frais peut donc avoir:

- un preview Office degrade ou indisponible si LibreOffice manque;
- un build website impossible localement;
- une console deployable via Docker/CI mais pas preparee par le setup local.

### Fichiers concernes

- `Makefile`, cible `setup`.
- `scripts/setup.sh`.
- `scripts/setup.ps1`.
- `seshat-backend/internal/officeconvert/officeconvert.go`.
- `seshat-ui/package.json`.

### Recommandation

Ajouter un vrai bootstrap de dependances systeme avec detection par OS:

- Windows: detecter `soffice.exe`; si absent, installer LibreOffice via
  `winget install TheDocumentFoundation.LibreOffice` si disponible, sinon
  proposer `scoop`/`choco`, sinon afficher une instruction claire.
- macOS: detecter `/Applications/LibreOffice.app/.../soffice`; si absent,
  `brew install --cask libreoffice` si Homebrew est disponible.
- Linux:
  - Debian/Ubuntu: `sudo apt-get install -y libreoffice`
  - Fedora/RHEL: `sudo dnf install -y libreoffice`
  - Arch: `sudo pacman -S --noconfirm libreoffice-fresh`
  - openSUSE: `sudo zypper install -y libreoffice`
  - Alpine: `sudo apk add libreoffice`

Ajouter aussi un flag:

- `SKIP_LIBREOFFICE=1` pour les environnements CI/minimaux.

Puis etendre setup pour installer les trois frontends:

- `seshat-ui`
- `seshat-console`
- `website`

Ne pas forcer tous les builds lourds par defaut: un bon compromis serait:

- `make setup`: dependances + verification rapide.
- `make setup-build`: dependances + build complet.
- `make setup-desktop`: seulement desktop.
- `make setup-web`: console + website.

## Priorite 2 - Accelerer `make deploy-up`

### Probleme

La cible `deploy-up` fait un `docker compose up --build -d` sur toute la
stack. Cela force:

- build Go de `seshat-server`;
- build Node de `seshat-console`;
- pull/lancement de `docling`, image lourde de plusieurs Go;
- pull/lancement de MinIO meme si le stockage S3 n'est pas active;
- pull/lancement de SearXNG + Valkey meme si le web search local n'est pas
  necessaire;
- attente de healthchecks, notamment docling avec `start_period: 90s`.

`seshat-server` depend de `docling` en `service_healthy`, donc meme si docling
est fonctionnellement optionnel, il bloque le demarrage du serveur dans la
stack compose.

### Fichiers concernes

- `Makefile`, cible `deploy-up`.
- `deploy/docker-compose.yml`.
- `deploy/.env.example`.
- `deploy/README.md`.

### Recommandation

Introduire des profils Docker Compose:

- core par defaut: `postgres`, `mailpit`, `seshat-server`, `seshat-console`.
- `--profile docs`: `docling`.
- `--profile search`: `searxng`, `searxng-redis`, `searxng-secret-key`.
- `--profile s3`: `minio`, `minio-createbucket`.
- `--profile full`: tout.

Ensuite changer les cibles Make:

- `make deploy-up`: core rapide, sans docling/minio/searxng.
- `make deploy-up-full`: stack complete.
- `make deploy-up-docs`: core + docling.
- `make deploy-up-search`: core + searxng.
- `make deploy-pull`: pre-pull explicite des images lourdes.
- `make deploy-build`: build images sans demarrer.

Changer aussi la dependance serveur:

- retirer `docling: condition: service_healthy` de `seshat-server.depends_on`
  pour que docling reste optionnel;
- laisser `SESHAT_SERVER_DOCLING_URL` vide par defaut dans la stack core;
- l'activer seulement via profil docs/full.

Garder `docling` disponible, mais ne pas le rendre bloquant au boot.

## Priorite 3 - Corriger les versions d'outillage

### Probleme

Les scripts setup disent Node.js 20+, alors que:

- `seshat-ui/package.json` demande `node >=22 <25`;
- la CI utilise Node 22;
- `seshat-console/Dockerfile` utilise Node 22.

Le repo Go declare aussi `go 1.26.5`, alors que les commentaires setup parlent
encore de Go 1.21+.

### Recommandation

Mettre a jour les scripts et docs:

- Node.js 22+ partout.
- Go 1.26+ partout, ou reduire le `go.work` si le projet doit vraiment
  supporter Go 1.21+.

Ajouter une verification simple dans setup:

- lire `go.work` pour la version Go minimale attendue;
- lire `seshat-ui/package.json` pour la contrainte Node, ou au minimum
  centraliser la version dans une constante commune.

## Priorite 4 - Corriger `make lint`

### Probleme

La cible `lint` contient une ligne staticcheck manifestement corrompue:

`staticcheck 1000 4 24 27 30 46 100 114 983 984 1000LINT_PACKAGES)`

Cela ressemble a un reste d'edition ou a une substitution Make cassee.

### Recommandation

Remplacer par:

`staticcheck $(LINT_PACKAGES)`

ou par une cible plus stricte:

`staticcheck ./seshat-backend/... ./seshat-server/...`

Ajouter `make lint` a la verification locale apres correction.

## Priorite 5 - Clarifier les frontends

Le monorepo contient trois frontends:

- `seshat-ui`: desktop Electron.
- `seshat-console`: console admin web deployee avec `seshat-server`.
- `website`: site marketing/docs.

Le setup local ne reflete pas cette structure. Il faut documenter et outiller
chaque surface:

- `make desktop-install`, `make desktop-build`, `make desktop-dev`
- `make console-install`, `make console-build`, `make console-dev`
- `make website-install`, `make website-build`, `make website-dev`
- `make install-all`
- `make build-all`

Cela evitera que `website` soit oublie, comme vu pendant l'audit.

## Backend desktop (`seshat-backend`)

Points forts:

- bonne separation services/API/db;
- tests presents sur agents, api, docconvert, knowledge, mcp, memories, plans,
  preferences, query, quotas, settings, skills, workflows;
- conversion document native-first pour DOCX/PPTX/XLSX/PDF text-layer avant
  docling, ce qui reduit la dependance a docling;
- LibreOffice isole par profil temporaire et serialise par mutex, bon choix
  pour eviter les locks `soffice`.

Ameliorations:

- exposer un endpoint/system status qui indique clairement si LibreOffice est
  detecte, comme docling;
- afficher dans l'UI une degradation explicite quand LibreOffice manque;
- tester `officeconvert` avec un faux binaire `soffice` pour couvrir les args
  et le timeout sans dependance systeme;
- considerer une file d'attente/limiteur pour conversions lourdes afin de ne
  pas bloquer l'experience si plusieurs documents sont ouverts.

## Serveur cloud (`seshat-server`)

Points forts:

- domaine serveur riche: IAM, organisations, roles, policies, automation,
  knowledge, memory, MCP, web search settings;
- tests nombreux sur IAM/API/knowledge/automation;
- console servie via nginx reverse-proxy same-origin, ce qui simplifie CORS;
- Postgres par defaut en deploy, bon choix pour multi-utilisateur.

Ameliorations:

- scheduler indique comme single-instance: il faut eviter toute scalabilite
  horizontale tant qu'il n'y a pas de lock distribue;
- `/metrics` public selon docs: acceptable localement, mais a proteger en
  production par reverse proxy ou bind prive;
- `docling` ne doit pas etre une dependance bloquante du serveur dans compose;
- MinIO ne doit pas etre requis par defaut quand `SESHAT_SERVER_STORAGE_PROVIDER`
  est vide.

## Desktop Electron (`seshat-ui`)

Points forts:

- securite Electron correcte: `nodeIntegration: false`,
  `contextIsolation: true`, `sandbox: true`;
- CSP stricte en mode package;
- liens externes filtres avant `shell.openExternal`;
- IPC centralise via preload.

Ameliorations:

- la passerelle preload expose beaucoup d'actions; auditer chaque handler IPC
  pour validation de schema stricte cote main process;
- `openPath`, `showFile`, `readFileDataURL`, upload et file-content doivent
  rester bornes a des chemins autorises;
- ajouter des tests unitaires pour `url-safety`, runtime path resolution et
  handlers IPC critiques;
- ajouter une verification UX visuelle automatisable sur les pages de chat,
  settings, workflows, previews DOCX/PDF/XLSX.

## Console admin (`seshat-console`)

Points forts:

- build OK;
- routing protege par roles;
- API typee depuis OpenAPI;
- structure claire par pages/domaines.

Ameliorations:

- verifier que `src/api/schema.d.ts` est toujours regenere dans CI quand
  `openapi.yaml` change;
- ajouter une check CI qui echoue si `npm run api:generate` produit un diff;
- surveiller le bundle: certains chunks sont lourds (`ConsoleTable`,
  workspace chat, antd/select). Ce n'est pas bloquant mais a profiler si la
  console devient lente.

## Website

Probleme observe:

- build KO localement car dependances non installees (`tsc` introuvable).

Recommandation:

- inclure `website` dans setup ou ajouter `make website-install`;
- ajouter un `make website-build`;
- eviter que `generate-sitemap.mjs` modifie `public/sitemap.xml` pendant une
  simple tentative de build si l'utilisateur ne s'attend pas a des changements
  de fichiers.

## CI/CD

Points forts:

- detection de changements par zone du monorepo;
- gate final qui accepte `skipped` comme OK pour les jobs conditionnels;
- CI couvre backend, desktop, console, website selon diff.

Ameliorations:

- la detection `changes` ne tient pas compte de fichiers racine qui impactent
  tout, par exemple `Makefile`, `.dockerignore`, scripts communs, deploy,
  configs TypeScript partagees;
- ajouter les scripts communs aux filtres pertinents;
- ajouter une job compose smoke test minimale pour `deploy-up` core une fois
  les profils introduits;
- ajouter la verification de generation OpenAPI console.

## Ordre de correction recommande

1. Corriger `make lint`.
2. Ajouter LibreOffice dans setup Windows/Linux/macOS avec `SKIP_LIBREOFFICE=1`.
3. Refactorer setup en cibles par surface: desktop/console/website/all.
4. Introduire les profils Docker Compose et rendre `deploy-up` core rapide.
5. Ajouter `deploy-up-full`, `deploy-up-docs`, `deploy-up-search`, `deploy-up-s3`.
6. Harmoniser Node 22+ et Go 1.26+ dans docs/scripts.
7. Ajouter status LibreOffice dans backend/UI.
8. Ajouter CI check OpenAPI schema generation.
9. Ajouter smoke test compose core.
10. Auditer les handlers IPC desktop avec tests de validation/chemins.
