# Hooks

`/orgs/:id/automation/hooks` — Organization → Automation → Hooks

## What it's for

Org-shared shell commands that run *before* a matching tool call
(PreToolUse) — a guardrail, not an action. The command's exit code
decides what happens: `0` allows the call, `2` denies it, `49` halts the
whole turn. Desktop-only — never executed by the shared server, since
running an arbitrary shell command server-side has no sandbox to run it
in safely.

## How to use it

"New hook" needs a command and, optionally, a matcher — a regex against
the tool name; empty matches every tool. A disabled hook isn't offered
for approval on any device at all, not just inactive.

Same "two separate decisions" pattern as [MCP Servers](../ai-core/mcp-servers.mdx):
defining a hook here doesn't make it run anywhere. Each device's own
user has to approve it explicitly before it executes anything, exactly
like an org-shared MCP server.
