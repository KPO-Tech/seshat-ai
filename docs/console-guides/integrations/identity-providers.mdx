# Identity Providers

`/orgs/:id/integrations/providers` — Organization → Integrations → Integrations → Identity Providers

## What it's for

Upstream identity providers (OIDC/OAuth2/SAML) this organization trusts
— members log in *through* one of these instead of (or in addition to)
a password. The reverse direction from [Applications](./applications.mdx):
here, this organization is the client of someone else's identity system.

## How to use it

OIDC/OAuth2 need a Client ID/secret plus the standard endpoint URLs
(issuer, discovery, authorization, token, userinfo, JWKS — a discovery
URL alone usually fills the rest at login time). SAML instead needs a
metadata URL or entity ID/SSO URL/certificate. "Allowed domains" can
restrict signup/auto-link to specific email domains; "Auto-link" matches
an incoming login to an existing account by email instead of always
creating a new one.

The Health column reflects whether a real login through this provider
has ever actually completed — separate from "Enabled" (which only says
the connection is turned on, not that it works). It stays "No activity
yet" until someone actually logs in through it once.
