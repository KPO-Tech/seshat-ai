# Financial Model — Infrastructure, AI Model, and Team Costs

Working numbers, not a final budget. Built to answer three questions raised directly: what does it cost to deploy Seshat (for us, or for a client), what does it cost to run on Chinese vs. American model providers, and what does a first hire cost — so we can work out what to charge and what margin is realistic, for an investor conversation.

**Method:** every figure below comes from a live web search (August 2026), cited at the point of use. Nothing here has been validated against real production load — treat these as first-pass estimates good enough to reason about pricing and margin, not as a guarantee. Section 5 lists exactly what still needs real-world verification before this becomes a number anyone commits to.

Two deployment scenarios are costed throughout, per the decision to pursue both:
- **Scenario A — Seshat-hosted (managed/subscription):** we pay the infrastructure, we bill a recurring price.
- **Scenario B — Client-hosted (self-hosted/sovereign):** the client pays their own infrastructure, we bill setup + maintenance only. This isn't a fallback — it's the same self-hosted/data-sovereignty pitch already core to the Case 3 offer in `7.go-to-market-africa.md`.

Two sizes are costed throughout:
- **Small** — 5 to 20 users (Case 1/2-shaped customer).
- **Medium** — 50 to 200 users (Case 3-shaped customer).

## 1. Infrastructure cost

What needs to run, beyond what's embedded in the desktop app (which costs nothing to "deploy" — it just runs on the user's machine): `seshat-server`, `seshat-console`, PostgreSQL, Docling (document conversion — noted in `ROADMAP.md` as a ~5GB CPU-only image running PyTorch + RapidOCR + layout models, the heaviest single piece), SearXNG (web search), and later some Python MCP servers (typically light).

### Small deployment (5–20 users)

One box is enough at this scale. Docling's model-loading footprint is the reason to size up rather than run everything on the cheapest tier.

| Provider | Spec | Monthly cost |
|---|---|---|
| Hetzner (CPX-class, 8 vCPU / 16 GB) | covers server + console + Postgres + SearXNG + Docling | ≈ €40–55 (~$45–60) |
| DigitalOcean (dedicated-CPU equivalent) | same footprint | ≈ $84–150 |

Hetzner is meaningfully cheaper for identical specs and is the reference point for price-per-spec in the VPS market this year — worth defaulting to it unless there's a reason to need DigitalOcean's ecosystem or a specific African/EU presence Hetzner doesn't offer.

**Scenario A (we host):** ≈ $50–60/month infrastructure, before LLM usage (section 2).
**Scenario B (client hosts):** $0 infrastructure cost to us — but this is still the spec we'd recommend the client provision, and the number that anchors a setup-fee estimate.

### Medium deployment (50–200 users)

Docling gets split onto its own node once load grows, and the database benefits from being separate from the app server — roughly 3 nodes instead of 1.

| Provider | Spec (combined across nodes) | Monthly cost |
|---|---|---|
| Hetzner (CCX-class, ~24 vCPU / 48 GB combined) | app node + Docling worker node + DB node | ≈ €150–280 (~$165–305) |
| DigitalOcean equivalent | same footprint | ≈ $350–650 |

Plus, at either size: domain, SSL, backups, basic monitoring — call it $10–25/month, not broken out further here.

**Sources:** [Hetzner Cloud pricing 2026](https://deployhandbook.com/pricing/hetzner), [Hetzner price adjustment notice](https://docs.hetzner.com/general/infrastructure-and-availability/price-adjustment/), [DigitalOcean Droplet pricing](https://www.digitalocean.com/pricing/droplets), [DigitalOcean pricing breakdown](https://kuberns.com/blogs/digitalocean-pricing/).

**Pattern:** at comparable "workhorse" tiers, Chinese providers run roughly **5–8x cheaper per token** than American flagship models. Seshat already supports Z.ai and MiniMax as first-class providers (`README.md`'s provider list), so this isn't a hypothetical switch — it's a default-provider decision.

**Kimi is the exception that proves the pattern isn't "Chinese = cheap" automatically.** Its cheaper tier (K2.5) is still meaningfully more expensive than GLM-4.6, MiniMax, or DeepSeek — and its flagship (K3) is priced at parity with American flagships ($3/$15, identical to Claude Sonnet's standard rate), not in the discount tier at all. Provider choice needs to be made model-by-model, not nationality-by-nationality. Kimi also isn't in Seshat's current native provider list (`README.md`) — reachable today only through OpenRouter (already supported), at OpenRouter's markup, unless direct integration gets added later.

**GLM-5.2 is the middle tier worth knowing about.** At $1.40/$4.40, it's about 3x GLM-4.6's price — but still roughly 2–3x cheaper than American flagships, positioned by Z.ai as noticeably stronger on long context, coding, reasoning, and tool use. A sensible "pro" option: more capable than GLM-4.6 for harder tasks, still meaningfully cheaper than going American.

### Translating this into cost per user/month

Assumption stated explicitly (adjust as real usage data comes in): a business-chat user, not a heavy coding-agent loop, runs roughly 30 conversational exchanges/day, averaging ~2,000 input + 400 output tokens per exchange (includes conversation history/context overhead) — about 1.8M input + 360K output tokens/month/user.

| Provider tier | Cost/user/month |
|---|---|
| Chinese (GLM-4.6) | ≈ $1.40 |
| Chinese (DeepSeek V4-Pro) | ≈ $1.10 |
| Chinese (GLM-5.2, "pro" tier) | ≈ $4.10 |
| American (Claude Sonnet, intro pricing) | ≈ $7.20 |
| American (Claude Sonnet, standard pricing from Sept 1) | ≈ $10.80 |
| American (GPT-5.4) | ≈ $10.50 |

**Recommendation this supports:** default to a Chinese provider (GLM-4.6 or DeepSeek) as the cost-optimized tier for Cases 1 and 2, where margin matters most and the customer has no existing model preference, with GLM-5.2 as a paid upgrade for harder tasks. Keep American models available as an explicit, priced-higher option — mainly for Case 3 clients who already have a vendor relationship or a compliance reason to prefer them (Bring Your Own AI already covers this in `5.business-strategy.md`).

**Sources:** [Anthropic pricing](https://www.cloudzero.com/blog/claude-api-pricing/), [OpenAI pricing](https://www.cloudzero.com/blog/openai-pricing/), [Gemini pricing](https://www.cloudzero.com/blog/gemini-pricing/), [GLM-4.6 pricing](https://openrouter.ai/z-ai/glm-4.6), [MiniMax pricing](https://developer.puter.com/tutorials/minimax-api-pricing/), [DeepSeek pricing](https://www.tldl.io/resources/deepseek-api-pricing).

## 3. Team cost — first hire (bilingual EN/FR sales)

Decided: based in West Africa, not remote — for credibility at this stage.

Local Ghana benchmarks found (Accra):
- General sales & marketing representative: ≈ GHS 7,022/month average (≈ $465, using the ≈15 GHS/USD implied by the source below).
- Territory sales representative: ≈ GHS 4,547/month average (≈ $300).
- Country-wide average salary, all roles: ≈ GHS 5,000/month (≈ $330).

None of this data is specific to a *bilingual* EN/FR sales hire — French speakers are relatively rare in anglophone Ghana, which should command a premium over the general sales-rep benchmark above. No direct comparable was found; broader "French-speaking sales Africa" listings ($41k–$110k/year) are for internationally-facing remote roles targeting all of Francophone Africa, not a like-for-like comparison for a locally based Ghana hire.

**Working estimate (Ghana):** $500–900/month (≈ GHS 7,500–13,500), i.e. roughly 1.1x–2x the general Accra sales-rep benchmark, to account for the bilingual premium and sales experience. **This is the softest number in the model — worth checking against a local recruiter or job board before it goes into anything shown to an investor.**

### Benin comparison, requested directly

Benin is Francophone — French fluency is the norm there, not a premium. That flips the bilingual-scarcity logic from Ghana: in Benin, *English* would be the harder-to-find skill and the one commanding a premium, not French.

| Metric | Benin |
|---|---|
| National minimum wage (SMIG) | 52,000 XOF/month (≈ $85) |
| Average salary, all roles | 120,000 XOF/month (≈ $215) |
| Median salary (most workers are below the average — high inequality) | 40,000 XOF/month (≈ $72) |
| Living wage estimate, Cotonou | 90,000–110,000 XOF/month (≈ $160–195) |
| Sales representative in commerce, 6–10 years experience + higher education | 420,000 XOF/month (≈ $735) |

At the general/entry-mid level, Benin (~$215/month average) is genuinely cheaper than Ghana (~$330/month average) — matches the intuition. But that one directly comparable sales-specific figure (~$735/month) is for someone senior (6–10 years, higher education) and comes out *higher* than Ghana's general sales-rep benchmark — not a clean like-for-like, since Ghana's number isn't broken out by seniority the same way. The honest read: Benin is likely cheaper for a similar experience level, but the data doesn't prove it as cleanly as the headline averages suggest.

**A separate question worth deciding, not a cost one:** the reason given for ruling out full remote was in-person credibility. Someone based in Benin is still remote relative to the Ghana market being targeted — cheaper on paper doesn't solve the "needs to look serious in Ghana" problem unless this person relocates to Ghana, splits time there, or the role gets redefined (e.g., founder covers Ghana directly, Beninese hire covers Francophone West Africa — Benin, Togo, Côte d'Ivoire — as a separate, genuinely well-matched market for a French-first hire).

**Sources:** [Glassdoor — Accra sales rep salaries](https://www.glassdoor.com/Salaries/accra-ghana-sales-representative-salary-SRCH_IL.0,11_IM1421_KO12,32.htm), [Average salary Ghana 2026](https://remotepeople.com/countries/ghana/average-salary/), [Territory sales rep Accra](https://worldsalaries.com/average-territory-sales-representative-salary-in-accra/ghana/), [Cost of hiring in Benin 2026](https://www.playroll.com/employment-cost/benin), [Benin minimum wage](https://remotepeople.com/countries/benin/employer-of-record/minimum-wage/), [Average salary Benin](https://wage.is/benin/).

## 4. Putting it together

### Scenario A — small client, Seshat-hosted (12 users, midpoint of 5–20)

| Line | Monthly cost |
|---|---|
| Infrastructure | ≈ $55 |
| LLM (Chinese default, 12 users × $1.40) | ≈ $17 |
| Misc (domain/SSL/backup/monitoring) | ≈ $15 |
| **Total direct cost** | **≈ $87/month** |

At a per-business subscription price — not per-seat, since Case 1/2 customers think in terms of "what does this cost me," not "per user" — of, say, **$150–250/month**, direct cost is a small fraction of revenue: strong gross margin at the unit level. The real constraint isn't unit margin, it's volume: the sales hire's $500–900/month salary needs roughly **3–6 small clients at this price point just to break even on that one hire**, before covering anything else (the founder's own time, further hosting, growth).

### Scenario B — client-hosted, any size

| Line | Who pays |
|---|---|
| Infrastructure | Client, directly |
| Setup (deployment, configuration) | One-time fee to us |
| Maintenance (updates, monitoring, support) | Recurring retainer to us |

No infra cost to us here, but also less recurring revenue per client than Scenario A unless the maintenance retainer is priced deliberately (not sketched with a number yet — needs its own pass once a first Scenario-B client is real).

### Medium client, Seshat-hosted (125 users, midpoint of 50–200)

| Line | Monthly cost |
|---|---|
| Infrastructure | ≈ $235 |
| LLM (mixed — assume some American-model usage at this tier, blended ≈ $4/user) | ≈ $500 |
| Misc | ≈ $25 |
| **Total direct cost** | **≈ $760/month** |

At enterprise-negotiated pricing (not sketched with a specific number — this tier is priced case by case, per `5.business-strategy.md`'s pricing philosophy), a single medium client plausibly covers the sales hire's salary on its own, if priced above roughly $1,500–2,000/month.

## 5. Risks and reserves — not to be forgotten

### Usage risk: flat pricing against variable cost

Section 4's margin is calculated against an *assumed* usage level, not a measured one. If a client genuinely over-uses the agent under a flat subscription price, the LLM cost line grows while the price doesn't — the seller absorbs 100% of that risk under pure flat pricing. A sensitivity check: at the small-client price point (~$150/month, ~$63/month margin before salary allocation), a 2–3x usage surprise is absorbed comfortably; a 5x surprise (going from ≈$17 to ≈$84/month of LLM cost) eats nearly all of it.

**Mitigation already available, not hypothetical:** Quotas — per-user usage counters, daily/monthly — already exist as a real platform feature (`README.md`'s feature list). This should be configured as a real guardrail per pricing tier from day one, not treated as optional. Practical options once real usage data exists: a capped/tiered plan (X messages included, overage billed), soft rate-limiting on heavy usage rather than a hard cutoff, or simply pricing with the sensitivity above already priced in as margin buffer.

### Startup credits — an immediate opportunity, not a "later" one

American AI/cloud providers run active startup credit programs, most of them accessible now rather than after volume is proven:

| Provider | Credit | Requirement |
|---|---|---|
| OpenAI | up to $500K, no equity | general startup program |
| Anthropic | $100K (general) to $500K (via Y Combinator) | pre-seed through Series A |
| Google Cloud | up to $350K (AI-focused path) | qualifying AI-first startup |
| AWS Activate | $1K self-serve entry tier; up to $300K AI tier | self-serve tier needs no backing; larger tiers need VC/accelerator backing |

This directly addresses the budget constraint noted earlier (no robust testing against paid models so far) — applying is plausibly higher-leverage right now than waiting for volume to negotiate with anyone.

**No equivalent found for Chinese providers.** What DeepSeek, Z.ai, and MiniMax are doing instead is aggressive public price-cutting (DeepSeek cut cache-hit pricing up to 90% at one point) rather than startup-credit programs. Reaching out directly once real volume exists is a normal, worthwhile move — but there's no confirmed formal partner/credit program to point to the way there is for OpenAI/Anthropic/Google/AWS. Treat it as "worth trying," not "expected."

### Enterprise due-diligence caveat for Chinese providers

Search results flagged this directly: enterprise buyers evaluating a China-model-based stack should weigh what isn't in the sticker price — enterprise support, formal SLAs, and Western compliance certifications are less mature at DeepSeek/Z.ai/MiniMax than at OpenAI/Anthropic/Google, and jurisdictional risk (data or requests touching a Chinese company's infrastructure) is a real objection a sophisticated Case 3 buyer may raise.

**This is where the self-hosted pitch and the cost pitch reinforce each other.** Several of these Chinese models ship as open weights (DeepSeek, GLM, MiniMax all have open releases) and can in principle be self-hosted entirely on the client's own infrastructure — which would neutralize the jurisdictional objection specifically (nothing calls out to a Chinese company's cloud at all) while keeping the cost advantage over comparable American models. **Not yet verified:** the actual hardware/GPU cost of self-hosting these specific model sizes at usable speed — needs its own costing pass before this becomes a real offer, not just a promising direction.

### Selling to clients who already have another AI vendor

Raised directly: a company already using another provider's API (e.g., an existing OpenAI relationship) doesn't need to be sold a replacement — they can adopt Seshat as an add-on layer on top of the API access they already pay for. This isn't a new technical capability to build: it's the existing **Bring Your Own AI** model (`5.business-strategy.md`) applied as a sales angle specifically for Case 3 prospects who already have a vendor relationship. It removes the single biggest objection that segment has (switching cost, sunk investment in another vendor) by not asking them to switch at all — Seshat sells the platform/orchestration layer, the client keeps paying their existing API bill directly, and Seshat's own LLM cost exposure for that client drops to near zero since the client's key covers it.

## 6. What still needs real-world verification before this goes to an investor

- **The bilingual salary estimate** — the softest number here, needs a local check, not just a global job-board search.
- **The usage assumption behind LLM cost/user** (30 exchanges/day, ~2,400 tokens/exchange) — invented to make the calculation concrete, not measured. Actual usage from the first real pilot (Case 1) should replace this as soon as it exists.
- **Infrastructure sizing** — based on Docling's documented footprint and general VPS specs, not a load test. Consistent with the testing gap already noted in `6.mvp.md`: nothing here has been proven under real concurrent load.
- **Scenario B's maintenance-retainer price** — not estimated yet at all, just flagged as needed.
- **Enterprise (medium/large) pricing** — deliberately left unspecified; `5.business-strategy.md` already commits to case-by-case pricing at that tier rather than a list price, and this model shouldn't contradict that by inventing one.
